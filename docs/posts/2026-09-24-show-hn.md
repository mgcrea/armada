Author here. I usually have 16+ Claude Code sessions running across a personal and a team account, plus Codex and Grok Build, and had no easy way to see which one was waiting for me or close to its context limit, and where my weekly limits would land before the reset.

Armada only reads what the agents already write to disk, and asks the installed claude for the usage numbers. It never reads or stores a token.

There is also a local MCP server (127.0.0.1), so a Claude session can see all the others, Codex and Grok Build included.

It can also warn you before a waiting session's prompt cache expires, since the next turn then writes the whole context back.

macOS only. Source is MIT: https://github.com/mgcrea/armada, the signed build is $14.99 with a 30-minute trial.

## Objections to expect

- **"CodexBar / ccusage already do this."** They cover one vendor or one account. Armada puts
  several vendors and accounts on one screen, with the sessions behind each number
  ([landscape.md](../landscape.md) lists them all).
- **"Two accounts to get around limits."** One Anthropic login with a personal and a team
  organization, the documented `CLAUDE_CONFIG_DIR` setup
  ([limits-accounts-and-terms.md](../limits-accounts-and-terms.md)).
- **"Why is an MIT app paid?"** The source builds with `make build`; what is sold is the signed,
  notarized binary.
